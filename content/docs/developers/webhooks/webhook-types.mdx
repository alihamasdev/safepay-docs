title: "Webhook structure and types"
description: "Learn which webhook types are sent for each event."

Each webhook payload contains a `type` that specifies the type of event triggered.

### Webhook structure

Each webhook event contains the following fields:

- `type`: Specifies the type of the event.
- `version`: Specifies the currently used version of the webhook event
- `data`: An object that contains the information about the event
- `delivery_attempts`: The number of times this event has attempted to reach your servers
- `next_attempt_at`: A timestamp indicating when this event will be re-sent for another attempt.

### Event types and examples

Safepay supports a broad range of webhook events that you can subscribe to.

Because we sometimes create new webhook types and event codes, you should set up your server to be able to accept webhooks of more types and receive more event code values than are listed below. When we create a new event code, you have to create new business logic if you want to use it.

Here are the currently supported events and example payloads for each.

### Payment events

- [`payment.succeeded`](/docs/developers/webhooks/webhook-types#paymentsucceeded): This event is fired when a payment is captured.
- [`payment.failed`](/docs/developers/webhooks/webhook-types#paymentfailed): This event is fired when an error occurs during the payment process
- [`payment.refunded`](/docs/developers/webhooks/webhook-types#paymentrefunded): This event is fired when a refund is made.
- [`authorization.succeeded`](/docs/developers/webhooks/webhook-types#authorizationsucceeded): This event is fired when a card payment has been authorized.
- [`authorization.reversed`](/docs/developers/webhooks/webhook-types#authorizationreversed): This event is fired when an authorization has been reversed.
- [`void.succeeded`](/docs/developers/webhooks/webhook-types#voidsucceeded): This event is fired when a payment or refund has been voided.

### Subscription events

- [`subscription.created`](/docs/developers/webhooks/webhook-types#subscriptioncreated): This event is fired when a customer subscribes to a recurring payment plan
- [`subscription.canceled`](/docs/developers/webhooks/webhook-types#subscriptioncanceled): This event is fired when a subscription is canceled
- [`subscription.ended`](/docs/developers/webhooks/webhook-types#subscriptionended): This event is fired when all billing cycles of a recurring payment subscription have been paid
- [`subscription.paused`](/docs/developers/webhooks/webhook-types#subscriptionpaused): This event is fired when a subscription has been paused
- [`subscription.resumed`](/docs/developers/webhooks/webhook-types#subscriptionresumed): This event is fired when a paused subscription has been resumed
- [`subscription.payment.succeeded`](/docs/developers/webhooks/webhook-types#subscriptionpaymentsucceeded): This event is fired when a recurring payment cycle has been paid
- [`subscription.payment.failed`](/docs/developers/webhooks/webhook-types#subscriptionpaymentfailed): This event is fired when a recurring payment cycle was not paid
